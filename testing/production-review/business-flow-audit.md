## 3. Impossible states / consistency checks

- **Searched-for and not found:** orphaned status transitions (all guarded in domain with tests), certificates active-after-expiry in public lookups (EffectiveStatus computed), report period duplicates (DB-unique), plan approval from Draft (HTTP-probe rejected), cross-org writes (probe-denied), unauthorized exports (probe-denied).
- **Found:** the `Received`-forever inbound state (W-1) — the one genuine dead-end; duplicate case codes possible under concurrency (W-3); soft-deleted parents leaving live `DocumentOwner`/`FileAttachment` rows + blobs (orphan accumulation — hygiene, backend doc §10).

## 4. Conclusion

Core officer-facing workflows are **complete, guarded, and proven at the browser+HTTP level** — the reporting state machine including the return path is among the best-evidenced parts of the system. The production-relevant workflow debt is concentrated in three places: the inbound-partner disposition dead-end (W-1 — must exist before any real partner integration goes live), the case-code race (W-3 — cheap fix: DB unique index + sequence-or-retry), and the concurrency-stamp round-trip (W-5 — decide, then implement consistently).
